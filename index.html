회사를 나온 뒤에는 방송통신대에서 컴퓨터과학을 공부하며 다른 진로도 준비해 봤습니다. 그 시간을 지나며 제가 정말 하고 싶은 일은 결국 서비스를 만드는 일이라는 걸 알게 됐고, 이번에는 데이터와 AI로 더 똑똑한 서비스를 만들고 싶어 2026년 AI 캠프에서 다시 배우기 시작했습니다. 지금은 데이터를 모으고, 검색하고, LLM으로 판단하는 서비스를 실제로 돌아가게 만드는 일을 하고 있습니다.

S-Brain

창업 아이템에 맞는 정부지원사업을 찾아, 사업계획서까지 만들어 주는 서비스

2026.08 – 2026.10 · 5명

제가 맡은 부분

공고 데이터와 매칭 파트를 혼자 만들었습니다. 매일 공고를 모으고, 맞는 공고를 찾아 주고, 공고 서버를 배포하는 것까지요.

정부지원사업 공고는 여러 기관에 흩어져 있고, 지원 자격은 첨부 문서 안에 숨어 있습니다. 그래서 창업자가 계획서를 다 쓴 뒤에야 자격이 안 된다는 걸 알게 되기도 합니다.

한 일

  • 공공 API 2곳에서 공고를 모아, PDF·HWP 첨부 본문 추출부터 LLM 자격 판정까지 14단계를 매일 자동으로 돌렸습니다.
  • 모집 상태·업력·신청자 유형으로 확실히 안 되는 공고만 먼저 거르고, 의미 검색과 키워드 검색을 합친 방식으로 순위를 매겼습니다. 지역은 거르지 않고 순위에서 뒤로 보냈습니다.
  • 다른 에이전트가 부르는 API 4개를 만들고, 공고 서버 배포(설치 스크립트, 매일 배치를 돌리는 systemd 타이머)를 맡았습니다. AWS 스택 구성은 팀원과 함께 했습니다.
  • Claude·Codex로 구현하고 서로 다른 모델이 교차 검수하게 해서, 품질을 테스트와 기록으로 확인했습니다.

자세히 보기 — 구조와 수치
전체 구조

팀이 만든 AWS CloudFormation 스택 하나로 네트워크, 서버, DB를 한 번에 만들고 지웁니다. 저는 그중 공고 서버 배포를 맡았습니다. 공고 서버는 바깥 주소가 없는 사설 영역에 두고, 웹 서버에서만 접근하게 했습니다.

공고와 벡터는 RDS MySQL에 저장하고, 서버가 켜질 때 메모리에 올려 직접 계산합니다. 처음에는 벡터 DB(Chroma)를 썼지만, 공고가 3천 건 정도라 전부 계산하는 쪽이 더 빠르고(0.77ms 대 3.41ms) 근사 검색 때문에 순서가 어긋나는 일도 없어서 바꿨습니다.

추천이 만들어지는 과정
  1. 정형 필터 — 모집 상태, 접수 마감, 업력, 신청자 유형(예비창업자·사업자)을 봅니다. 확실히 안 되는 공고만 빼고, 조건을 모르면 남깁니다.
  2. 하이브리드 검색 — 의미 검색(BGE-M3)과 단어 검색(BM25) 결과를 RRF로 합칩니다.
  3. 규칙 재정렬 — 지역이 다르거나 신청이 어려워 보이는 공고는 뒤로 보냅니다.
  4. 후보 10건 → 화면 3건 — 적합도와 가산점으로 3건을 고르고, 자격을 판정합니다.

PetTriage

반려동물이 무언가를 먹었을 때, "지금 병원에 가야 하나?"에 근거와 함께 답하는 AI

2026.07 – 2026.08 · 4명

제가 맡은 부분

3차에는 계정·반려동물·다이어리 백엔드와 AI 채팅 연결을, 4차에는 AWS 실서버 배포를 맡았습니다.

진단 대신, 근거 자료를 찾아 지금 해야 할 행동을 응급·지금 연락·곧 방문·관찰 4단계로 알려 주는 서비스입니다. 등급은 코드가 정하고, LLM은 그 위에서만 말하게 설계했습니다.

한 일

  • 회원가입·로그인과 반려동물 API를 처음 구현하고, 다이어리를 DB에 영구 저장하도록 바꿨습니다.
  • AI 그래프의 앞단 노드(질문 분류, 정보 추출, 근거 검색)를 구현하고, 그래프 엔진을 채팅 API에 연결했습니다.
  • 4차에는 채팅·대화 기록 화면을 Django로 옮기고, nginx로 Django와 FastAPI 경로를 나눴습니다.
  • ALB와 HTTPS 인증서, nginx, systemd로 서버를 구성하고 도메인까지 연결했습니다. 배포계획서도 작성했습니다.

AI가 답하는 흐름 (3차, 팀 설계)

LangGraph 노드 18개가 질문 분류 → 정보 추출 → 근거 검색 → 독성 계산 → 규칙 판정 → 답변 생성 → 검증 순서로 움직입니다. 체중당 독성 수치는 코드가 계산하고, 최종 등급은 규칙과 LLM 중 더 위험한 쪽을 따르기 때문에 LLM이 위험을 낮춰 말할 수 없습니다. 정보가 부족하면 최대 2번 되묻고, 범위 밖 질문은 거절합니다.

  • 외부 API 없이 사내에서 돌릴 수 있는 구조
